## 2. Термины

**Astor Butler** - цифровой ассистент для ресторана/площадки, работающий через Telegram и другие согласованные каналы, с FSM как источником состояния диалога.

**FSM** - сценарная модель состояния, в которой фиксируется текущий шаг гостя, обязательные подтверждения, история и безопасные переходы.

**Saby** - внешняя система Saby, ранее известная как СБИС/sbis, включая ресторанный продукт Saby Presto, если он используется Заказчиком.

**Интеграция Saby** - отдельный внешний adapter/port для обмена статусами доступности, заявками и идентификаторами бронирования с Saby после получения подтвержденного API-контракта и доступов.

**Заявка гостя** - структурированный запрос гостя на бронирование, изменение, отмену или уточнение условий, созданный в Astor Butler.

**Подтверждение** - явное действие уполномоченного сотрудника Заказчика или согласованный confirmation workflow, без которого Astor Butler не считает бронирование финально подтвержденным.

## 3. Предмет договора

Исполнитель оказывает Заказчику услуги по проектированию, настройке, запуску и сопровождению Astor Butler для ресторана/площадки Заказчика, включая подготовку сценариев гостевого общения, обработку заявок на бронирование, уведомления команды и подготовку внешней интеграции с Saby.

Состав, этапы и критерии приемки услуг определяются настоящим договором и приложениями:

- Приложение N 1. Техническое задание;
- Приложение N 2. API-интеграция Saby и workflow подтверждения;
- Приложение N 3. Данные, согласия и персональные данные;
- Приложение N 4. Этапы, приемка и открытые вопросы.

## 4. Состав услуг

В базовый состав услуг входит:

- аудит текущего процесса ресторана/площадки;
- настройка Telegram/FSM-сценариев для первичного контакта и бронирований;
- подключение веб/Telegram каналов, если доступы и технические условия предоставлены;
- настройка хранения сообщений, заявок, согласий и служебных событий в существующей базе;
- настройка уведомлений оператору/хостес/менеджеру через согласованный канал;
- подготовка или подключение AI-слоя для классификации намерений, нормализации текста и резюме для команды;
- подготовка external reservation port для Saby;
- тестирование smoke/E2E в согласованном окружении;
- документация по эксплуатации, переменным окружения, откату и приемке.

Интеграция с реальным Saby API выполняется только после предоставления Заказчиком или вендором подтвержденного API-контракта, доступа, полномочий, тестового контура и правил тарификации.

Замечания принимаются только в пределах согласованного объема этапа. Новые функции, новые каналы, новые сценарии и изменения бизнес-процесса оформляются через change request.
