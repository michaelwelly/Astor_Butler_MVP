# Video database — `videos.json`

The full C3AG portfolio inventory (197 records) pulled from the Yandex.Disk
archive `disk.yandex.ru/d/oopTdDN0CTuIig`.

**The video files themselves are NOT here.** The masters are ~135 GB — far too
big for the repo, and they're masters, not web renditions. This file stores only
metadata + a slot for where each clip is hosted.

## How a video goes live on the site

1. Host the clip somewhere reachable by the browser:
   - a light web rendition dropped in `frontend/public/portfolio/`, **or**
   - an absolute URL (Object Storage / CDN once the backend pipeline exists).
   - preferred production path: run `frontend/scripts/object-storage-publish.mjs`
     for selected records; it uploads web/preview/poster assets to Yandex Object
     Storage and patches this JSON.
2. Open its record in `videos.json` and fill:
   - `src` — the hosted video URL (`"clip.mp4"` → `/portfolio/clip.mp4`,
     `"/local/path"`, or `"https://…"`),
   - `poster` — optional still,
   - `objectKey` / `posterObjectKey` / `previewObjectKey` — Object Storage keys
     when the asset lives in the C3 media bucket,
   - `previewUrl` — lightweight autoplay-safe rendition for cards,
   - `adaptedUrl` — cropped/subtitled/site-specific version when it differs from
     the source,
   - `originalUrl` — public or internal pointer to the master export,
   - `duration` — optional, `"01:40"`,
   - fix `direction` / `orientation` / `featured` if needed.

Any record with a non-empty `src` shows up in the catalog automatically
(`lib/video-db.ts` → `lib/portfolio.ts`). Records without one stay in the DB as
"not yet hosted" and don't render — so the site keeps showing the sample set
until you start hosting real clips.

## Fields

| field | meaning |
|-------|---------|
| `id` | stable internal id |
| `title` | derived from the filename — edit freely |
| `category` | original Yandex folder (reference) |
| `direction` | `events` \| `reels` \| `commercials` — which site row it lands in |
| `sourcePath` | path inside the Yandex.Disk archive (reference only) |
| `sizeBytes` | master size (reference only) |
| `src` / `poster` | **you fill** — where it's hosted |
| `objectKey` / `posterObjectKey` / `previewObjectKey` | S3/Object Storage keys for web video, poster and autoplay preview |
| `previewUrl` | lightweight card/autoplay version |
| `adaptedUrl` | version adapted for the site, social cut, subtitles, crop, etc. |
| `originalUrl` | master/original pointer, usually Yandex.Disk or cold storage |
| `duration` / `featured` / `orientation` | optional presentation fields |

## Product feed mapping

The homepage work feed is product-led now: rows follow `lib/products.ts`
order and use `clipFolders` to pick records from this database. Keep product
names, prices and terms in `lib/products.ts`; keep media metadata here. When
Mongo/Object Storage replaces this local JSON, preserve the same fields so the
frontend can switch transport without rewriting the UI.

Regenerated by `scratchpad/crawl.py` + `build_db.py` if the archive changes.

## Publishing to Object Storage

```bash
node frontend/scripts/object-storage-publish.mjs --ids 117-2,070-2-basta-aftermovie-part-2
node frontend/scripts/object-storage-publish.mjs --direction reels --max-mb 80 --limit 10
```

The script requires local `ffmpeg`, `ffprobe` and Yandex Cloud CLI `yc`. It
downloads the selected Yandex.Disk master, renders `web.mp4`, `preview.mp4` and
`poster.jpg`, uploads them to `c3ag-media` with `public-read`, then stores:

- `objectKey` → full site-ready video;
- `previewObjectKey` → short autoplay-safe card video;
- `posterObjectKey` → still image.

Frontend resolution uses the explicit `s3:` prefix and
`NEXT_PUBLIC_MEDIA_BASE_URL`, so object keys do not collide with legacy bare
filenames in `frontend/public/portfolio/`.
